2. Project Architecture

System Components

  • Data Sources: Kaggle datasets, MySQL databases, CSV files
  • Processing Layer: Python-based ETL pipeline
  • Storage Layer: Google BigQuery data warehouse
  • Presentation Layer: Streamlit dashboard for ETL monitoring

Technology Stack

  • Python (Pandas, NumPy) for data processing
  • Streamlit for interactive ETL dashboard
  • Google Cloud BigQuery for data warehousing
  • SQL for data transformation and querying

Key Architecture Benefits

Modular design enables independent scaling of extraction, transformation, and loading processes while maintaining a unified workflow through the Streamlit interface.

3. Methodology & Workflow

ETL Process Flow

  1. Extract: Retrieve data from Kaggle, MySQL, and local CSV files (customers, orders, products, payments, reviews)
  2. Transform: Clean, merge, and restructure data using pandas DataFrame operations
  3. Load: Upload to BigQuery in star schema format
  4. Analyze: Create data marts, aggregation tables, and KPIs

Implementation Approach

  • Manual step-by-step execution for testing and validation
  • Automated full pipeline for production deployment
  • Progress tracking and status monitoring
  • Data quality validation at each stage

Streamlit Dashboard Integration

Interactive web interface provides real-time visibility into pipeline execution with progress bars and status indicators for each step of the ETL process.

6. Implementation Challenges

Data Quality Issues

  • Handling missing values across multiple datasets
  • Data type inconsistencies between sources
  • Entity resolution across different systems
  • Standardizing product categories and translations

Technical Challenges

  • Integrating multiple data sources with different schemas
  • Optimizing large data transformations with limited memory
  • Managing BigQuery upload limitations and quotas

Process Challenges

  • Balancing automation with visibility
  • Error handling and recovery strategies
  • Pipeline monitoring and maintenance
  • Managing incremental vs. full loads

Resolution Approach

Implemented robust data validation, cleansing routines, and a modular architecture that allows for targeted error handling and component reuse.
